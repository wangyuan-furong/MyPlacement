# 任务 4：初始布局实现与验证

## 与参考资料对应的修改

- 随机布局保留固定随机种子，在核心区域内随机生成单元左下角坐标。
- 聚类布局每次选择当前连接权重最大的簇对，合并后按
  `W(A∪B,C) = W(A,C) + W(B,C)` 更新连接权重，同时更新面积加权质心。
  最大堆中的失效记录延迟删除，并定期重建堆控制内存。
- 簇内以最大成员宽高和成员数量确定矩形网格，逐格放置单元。
  对最后一行未填满的情况，按实际成员面积校正格点质心；靠近边界时平移矩形框。
  网格框超过核心区域时压缩，允许初始布局重叠。不同簇之间也没有合法化约束。
- 二次解析布局对每个网络的引脚对使用
  `wx = 1 / ((P-1) * max(abs(pinPX-pinQX), MIN_DIST))`，y 方向同理。
  `P` 为当前网络引脚数，`MIN_DIST = 1` 为最小距离；可移动-可移动和可移动-终端连接
  均采用该归一化。单元对去重仅用于矩阵存储，各引脚对的贡献仍分别累加。
- 使用 Eigen BiCGSTAB 和 IdentityPreconditioner，完整存储矩阵上下三角。
  线性系统内部使用 double，单元坐标仍使用项目原有的 float。
- 无固定终端的可移动连通分量各选一个参考单元，将其中心约束到核心区域中心，
  消除整体平移自由度。单独的无连接单元也按此处理。
- 检查求解状态、有限数值和显式相对残差。未达容差但有限且改善残差的近似解可继续用于
  下一轮重加权，并输出提示；数值无效或残差恶化时保留上一轮位置并终止。
- 每次线性求解最多 500 步，目标相对残差为 `1e-5`；外层最多 20 轮。
  至少执行 5 轮，且线性求解成功、显式残差达标、最大位置变化小于核心区域最大边长的
  `1e-4`（边长小于 1 时按 1 计算），才提前停止。
- 每轮求解后将单元限制在核心区域内。日志残差对应边界截断之前的线性解，
  不代表截断后的坐标仍满足原方程。

上述范围为任务 4；全局布局和合法化算法没有在本次修改中调整。

## 运行

在项目根目录：

```bash
cmake -S . -B build
cmake --build build -j 2
./build/myplace adaptec1/adaptec1.aux --initial-only
```

`--initial-only` 只执行任务 4，输出三种方法的 HPWL、耗时和 `output/init_*.bmp`。
不提供该参数时，继续执行原有的全局布局与合法化流程。

算法检查默认不构建，可按以下方式开启：

```bash
cmake -S . -B /tmp/myplacement-task4-build -DCMAKE_BUILD_TYPE=Release -DMYPLACEMENT_BUILD_TESTS=ON
cmake --build /tmp/myplacement-task4-build -j 2
ctest --test-dir /tmp/myplacement-task4-build --output-on-failure
```

## 比较分析的边界

- 随机布局不利用连接关系；逐单元放置的时间复杂度为 O(n)，允许重叠。
- 聚类布局利用连接强度，但矩形框仍可能相互重叠。构建连接图需要枚举各网络引脚对，
  工作量随各网引脚数平方之和增长；动态合并还需更新邻接表和堆。
- 二次解析直接利用引脚连接及偏移优化加权二次模型，允许重叠。
  每次线性求解的成本取决于稀疏矩阵非零元数及内部迭代次数，不能只按单元数估计。
- 当前数据中二次解析的 HPWL 最低、耗时最高；这是一组数据上的实测，不代表所有数据集的排序。
  还应结合布局图片、多个规模的数据及后续全局布局结果评价分布质量和适用规模。
